## 1. Executive Summary

Milestone V2.4 implements Pillar 3 of Phase 3: **Modern Analytics Transformation Migration to dbt Core**, replacing the custom Python-based transformation runner and SQL header parsing with an industry-standard **dbt Core (`dbt-postgres`)** project structure in `analytics_dbt/`.

Prior to V2.4, transformation models relied on custom comments (`-- Model:`, `-- Depends on:`) and in-house topological sorting. Milestone V2.4 achieves:
1. **Standardized dbt Project Architecture (`analytics_dbt/`)**: Configured with `dbt_project.yml` and `profiles.yml` declaring dedicated schemas (`staging` views, `intermediate` views, `mart` tables).
2. **26 Clean Staging Models (`models/staging/`)**: Fully migrated with `sources.yml` source declarations and Jinja `source('raw', '...')` macros.
3. **Phase 3 General Ledger Staging & Mart Integration**:
   - `stg_accounts`, `stg_fiscal_periods`, `stg_journal_entries`, `stg_journal_entry_lines`, `stg_currencies`, `stg_fx_rates`.
   - `dim_account`: Conformed Chart of Accounts dimension.
   - `fact_gl_journal_line`: Double-entry General Ledger fact table.
4. **Intermediate Business Logic Models (`models/intermediate/`)**:
   - `int_customer_scd2`: Slowly Changing Dimension Type 2 validity intervals.
   - `int_ar_aging_buckets`: Accounts Receivable aging buckets (`current`, `1-30_days`, `31-60_days`, `61-90_days`, `over_90_days`).
5. **Automated Schema & Custom Singular Tests**:
   - 79 automated column tests (`unique`, `not_null`, `accepted_values`, `relationships`).
   - Custom singular tests: `assert_trial_balance_debits_equal_credits.sql` and `assert_ar_allocation_parity.sql`.
6. **Programmatic Python Runner (`analytics/transform/dbt_runner.py`)**:
   - Python wrapper for executing `dbt parse`, `dbt compile`, `dbt run`, `dbt test`, and inspecting the compiled DAG manifest.

### 2. DAG Lineage & Dependency Resolution
- Replaced custom regex header parsing with native Jinja `ref()` expressions:
  - `fact_gl_journal_line` -> `dim_account`, `stg_journal_entries`, `stg_journal_entry_lines`.
  - `dim_account` -> `stg_accounts` -> `source('raw', 'accounts')`.
  - `fact_sales_line` -> `dim_customer`, `dim_product`, `stg_invoices`, `stg_invoice_lines`.
  - `dim_customer` -> `int_customer_scd2` -> `source('raw', 'customers')`.

### 3. Automated Data Quality Testing
- Schema Tests:
  - `unique` and `not_null` primary keys across all dimensional models.
  - `relationships` foreign key validation between facts and dimensions.
  - `accepted_values` validation on account types (`asset`, `liability`, `equity`, `revenue`, `expense`), normal balances (`debit`, `credit`), and aging buckets.
- Singular SQL Tests:
  - `assert_trial_balance_debits_equal_credits`: Mathematically verifies that total debits equal total credits across all posted General Ledger lines.
  - `assert_ar_allocation_parity`: Verifies that payment allocations do not exceed collected cash totals.

### 4. DbtRunner Integration Engine (`analytics/transform/dbt_runner.py`)
- Programmatic invocation of dbt CLI operations with isolated environment variable passthrough.
- Manifest loading and inspection utilities (`list_models()`, `get_model_dependencies(model)`).
