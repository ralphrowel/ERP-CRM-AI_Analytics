## 1. Executive Summary

Milestone V3.1 delivers enterprise multi-warehouse logistics capabilities to the ERP/CRM platform. Prior to V3.1, stock transfers between warehouses operated as single-step immediate posting events without intermediate logistics tracking, and replenishment was determined via ad-hoc global inventory thresholds.

Milestone V3.1 establishes:
1. **Granular Per-(Warehouse, Product) Replenishment Policies**: Distinct safety stock thresholds (`min_qty`), target stock levels (`max_qty`), discrete batch order sizes (`reorder_quantity`), and configurable sourcing types (`transfer` vs `purchase`).
2. **Two-Step In-Transit Stock Transfer Workflow**: Upgraded stock transfers into a 4-state lifecycle (`draft` -> `approved` -> `in_transit` -> `posted`) with explicit dispatch and receipt checkpoints, origin quantity deduction upon transit initiation, and weighted average cost (WAC) preservation at destination upon arrival.
3. **Automated Replenishment Evaluation & Transfer Generation**: An evaluation engine that scans stock balances across warehouses against active policies, identifies replenishment deficits, and generates batched draft transfer orders without disrupting human approval workflows.
4. **Resilient Application Lifecycle & Startup**: Hardened FastAPI startup lifespan handling to tolerate transient database connectivity issues in testing and local sandbox environments.

## 2. Architecture & Components Delivered

### 2.1 Multi-Warehouse In-Transit Workflow State Machine
```
[ Draft Transfer ]
       │
       ▼ (approve_stock_transfer)
 [ Approved ]
       │
       ▼ (dispatch_stock_transfer)
  [ In-Transit ] ──► Ledger 'transfer_out' posted at Origin Warehouse
       │             Origin quantity deducted; destination unaffected
       │
       ▼ (receive_stock_transfer)
   [ Posted ]    ──► Ledger 'transfer_in' posted at Destination Warehouse
                     Destination quantity added; Destination WAC blended
```

- **Origin Balance Deduction on Dispatch**: When goods are dispatched, quantity is immediately deducted from the origin warehouse balance to prevent phantom inventory or double allocation.
- **In-Transit Cost Tracking**: Goods in transit maintain their source unit cost across transit.
- **Cost Absorption on Receipt**: Upon arrival and receipt at the destination warehouse, the incoming quantity and cost are integrated into the destination warehouse's weighted average cost (WAC) using the standard perpetual inventory formula:
  $$\text{New WAC} = \frac{(\text{Current Qty} \times \text{Current WAC}) + (\text{Incoming Qty} \times \text{Transfer Unit Cost})}{\text{Current Qty} + \text{Incoming Qty}}$$

### 2.2 Reorder Policies & Replenishment Sourcing Engine
- **Table:** `warehouse_reorder_policies`
  - Unique constraint on `(warehouse_id, product_id)`
  - Check constraints enforcing `min_qty >= 0`, `max_qty >= min_qty`, `reorder_quantity > 0`, and `source_warehouse_id <> warehouse_id` for transfer sourcing.
- **Replenishment Evaluation (`evaluate_replenishment_suggestions`)**:
  - Compares physical on-hand balance against `min_qty`.
  - Calculates deficit: $\text{Deficit} = \max(\text{max\_qty} - \text{on\_hand}, 0)$.
  - Applies discrete batch ordering if `reorder_quantity` is defined:
    $$\text{Suggested Qty} = \lceil \text{Deficit} / \text{reorder\_quantity} \rceil \times \text{reorder\_quantity}$$
  - Inspects source warehouse stock availability when `sourcing_type == 'transfer'`.
- **Automated Transfer Generation (`auto_generate_replenishment_transfers`)**:
  - Groups suggested transfer items by `(source_warehouse_id, destination_warehouse_id)`.
  - Atomically creates `draft` `StockTransfer` documents with sequence numbers and line items for review.

## 4. API Endpoints Delivered

| Method | Endpoint | Description | Scope / Permissions |
|---|---|---|---|
| `POST` | `/api/v1/stock-transfers/{id}/approve` | Approve a draft stock transfer | `inventory:transfer:approve` |
| `POST` | `/api/v1/stock-transfers/{id}/dispatch` | Dispatch approved transfer into transit | `inventory:transfer:dispatch` |
| `POST` | `/api/v1/stock-transfers/{id}/receive` | Receive in-transit transfer into destination | `inventory:transfer:receive` |
| `GET` | `/api/v1/inventory/reorder-policies` | List replenishment policies with filters | `inventory:policy:read` |
| `POST` | `/api/v1/inventory/reorder-policies` | Create or configure a reorder policy | `inventory:policy:write` |
| `GET` | `/api/v1/inventory/reorder-policies/{id}` | Retrieve specific reorder policy | `inventory:policy:read` |
| `PUT` | `/api/v1/inventory/reorder-policies/{id}` | Update existing reorder policy | `inventory:policy:write` |
| `DELETE` | `/api/v1/inventory/reorder-policies/{id}` | Remove reorder policy | `inventory:policy:write` |
| `GET` | `/api/v1/inventory/replenishment/suggestions` | Evaluate active policies for stock shortages | `inventory:replenish:read` |
| `POST` | `/api/v1/inventory/replenishment/auto-generate` | Generate batched draft transfer orders | `inventory:replenish:write` |
