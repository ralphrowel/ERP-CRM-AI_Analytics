## 1. Executive Summary

Milestone V2.3 implements Pillar 2 of Phase 3: **Multi-Currency Operations & Foreign Exchange (FX) Engine**, empowering the ERP system to engage in cross-border commerce while preserving strict single functional base currency accounting (Philippine Peso - PHP) in compliance with Philippine Financial Reporting Standards (PFRS / IAS 21).

Prior to V2.3, the ERP system operated strictly in domestic PHP (ADR-0008). Milestone V2.3 delivers:
1. **ISO-4217 Currency Master Data Registry** with single base currency enforcement (`PHP`) and dynamic custom currency registration.
2. **Date-Effective Foreign Exchange (FX) Rates Engine** supporting direct rate lookup, automatic reciprocal (inverse) rate calculation, and historical audit tracking.
3. **Multi-Currency Subledger-to-GL Invoicing Pipeline** converting commercial amounts to base PHP using prevailing exchange rates while preserving line-item rounding parity.
4. **Automated Realized FX Gain / Loss Settlement Posting** calculating exact exchange differences when settling foreign receivables at differing exchange rates, posting automatically to Realized FX Gain (`4300`) or Realized FX Loss (`5300`) with zero centavo discrepancy.
5. **Real-Time Financial Statement Equilibrium** ensuring Realized FX gains/losses flow dynamically into the Income Statement and folded Balance Sheet equity maintaining `Assets == Liabilities + Equity + Net Income`.

## 2. Key Capabilities Delivered in V2.3

### 1. ISO-4217 Currency Master Data & Models (`app/modules/accounting/models.py`)
- **`Currency` Model**:
  - `code`: 3-character ISO code (Primary Key, uppercase).
  - `name`: Full currency description (e.g. "US Dollar", "Euro").
  - `symbol`: Commercial currency symbol (e.g. "₱", "$", "€").
  - `decimal_places`: Precision specification (2 standard, 0 for currencies like JPY).
  - `is_base`: Boolean flag strictly limited to one active base currency (`PHP`).
  - `is_active`: Soft deactivation flag.
- **`ExchangeRate` Model**:
  - `from_currency_code`: Foreign currency code FK.
  - `to_currency_code`: Counter currency code FK (typically base PHP).
  - `effective_date`: Date from which the rate is valid.
  - `rate`: Numeric(19, 6) precision rate (up to 6 decimal places).
  - `source`: Provenance tracking (e.g. "BSP", "manual", "reuters").
  - `uq_fx_rate_pair_date`: Unique constraint on `(from_currency_code, to_currency_code, effective_date)`.

### 2. General Ledger Chart of Accounts Expansion
Updated default Chart of Accounts (`DEFAULT_COA`) with dedicated foreign exchange accounts:
- `4300 Realized Foreign Exchange Gain` (Revenue, normal balance: credit)
- `4310 Unrealized Foreign Exchange Gain` (Revenue, normal balance: credit)
- `5300 Realized Foreign Exchange Loss` (Expense, normal balance: debit)
- `5310 Unrealized Foreign Exchange Loss` (Expense, normal balance: debit)

### 3. Date-Effective FX Resolution & Conversion Engine (`GLService`)
- **`get_exchange_rate(from_curr, to_curr, as_of_date)`**:
  - Chronological resolution: returns latest rate where `effective_date <= as_of_date`.
  - Identity matching: identical currencies (`USD` -> `USD` or `PHP` -> `PHP`) always resolve to `1.000000`.
  - Reciprocal resolution: if `USD` -> `PHP` is 50.0, querying `PHP` -> `USD` automatically resolves to `1 / 50.0 = 0.020000`.
- **`convert_amount(amount, from_curr, to_curr, as_of_date)`**:
  - Converts decimal monetary amounts using prevailing rate and executes banker's rounding (`round_money`) to preserve exact centavo precision.

### 4. Multi-Currency Subledger-to-GL Integration
- **Foreign Invoice GL Posting (`post_invoice_to_gl`)**:
  - Converts foreign invoice subtotal, taxes, and grand total to functional base currency (PHP).
  - Compensates for fractional centavo rounding splits to ensure `SUM(debits) == SUM(credits)`.
  - Includes foreign currency exchange rate annotations in journal line descriptions (e.g. `(USD 1000.00 @ 56.000000)`).
- **Automated Settlement & Realized FX Posting (`post_payment_to_gl`)**:
  - When payment rate strengthens ($1,000 USD invoiced at ₱56.00 settled at ₱58.00):
    - `Dr. 1120 Cash in Bank`: ₱58,000.00
    - `Cr. 1200 Accounts Receivable`: ₱56,000.00
    - `Cr. 4300 Realized FX Gain`: ₱2,000.00
  - When payment rate weakens ($1,000 USD invoiced at ₱56.00 settled at ₱55.00):
    - `Dr. 1120 Cash in Bank`: ₱55,000.00
    - `Dr. 5300 Realized FX Loss`: ₱1,000.00
    - `Cr. 1200 Accounts Receivable`: ₱56,000.00
  - Maintains strict double-entry balance without manual intervention.

### 5. REST API & RBAC Authorization (`app/modules/accounting/router.py`)
- `GET /api/v1/accounting/currencies` (`accounting:read`): Lists active currencies.
- `POST /api/v1/accounting/currencies` (`accounting:manage`): Registers new currency.
- `GET /api/v1/accounting/fx-rates` (`accounting:read`): Queries date-effective exchange rate.
- `POST /api/v1/accounting/fx-rates` (`accounting:manage`): Records or updates daily exchange rate.
- `POST /api/v1/accounting/fx-rates/convert` (`accounting:read`): Utility endpoint to convert amounts.
