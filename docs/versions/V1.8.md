# Milestone V1.8 Release Notes: Events, Notifications and Automation

**Release Date:** October 12, 2026  
**Status:** Completed  
**Branch:** `feat/v1.8-events-notifications-automation`

---

## 1. Executive Summary

Milestone V1.8 implements an asynchronous, highly resilient event-driven architecture for the ERP/CRM platform. It solves the critical operational requirement of decoupling business operations from side-effect delivery (emails, notifications, downstream jobs).

Using the **Transactional Outbox Pattern**, domain entity mutations and event records are committed together in the same atomic database transaction. An asynchronous **Outbox Worker** polls and dispatches events to idempotent handlers, guaranteeing **at-least-once delivery** with exponential backoff and transparent **dead-letter observability**.

Under this model:
- No HTTP request directly sends emails or external notifications, guaranteeing sub-second response times and zero partial failure inconsistencies.
- Scheduled checks automatically trigger business automation (past-due invoices, expired quotes, closing deals, delayed POs, low stock).
- In-app notifications with deduplication and unread counts are delivered seamlessly to users.

## 2. Key Capabilities Implemented

1. **Transactional Outbox Table (`outbox_events`)**:
   - `id`, `event_type`, `aggregate_type`, `aggregate_id`, `payload`, `attempts`, `available_at`, `processed_at`, `last_error`, `created_at`.
   - Optimized index on `(processed_at, available_at, attempts)` for ultra-fast polling.
   - Database migration `backend/migrations/versions/0017_events_notifications_outbox.py`.
2. **Resilient Outbox Worker (`OutboxWorker`)**:
   - Concurrent worker polling using `SELECT ... FOR UPDATE SKIP LOCKED` (Postgres) / atomic timestamp claiming (SQLite).
   - Exponential retry backoff ($2^{\text{attempts}}$ seconds) on transient handler failures.
   - Dead-letter state: permanently failed events after 8 attempts are quarantined with the full error trace preserved.
3. **Idempotent Handlers (`EVENT_HANDLER_REGISTRY`)**:
   - `approval_request.created`: notifies approver role and assignee.
   - `password_reset.requested`: dispatches reset email token via `EmailDispatcher`.
   - `sales.invoice_past_due`: generates overdue invoice notification.
   - `sales.quote_expired`: generates quote expiration alert.
   - `crm.opportunity_closing_soon`: notifies deal owner of closing milestone.
   - `purchasing.po_delayed`: alerts purchasing team of overdue supplier delivery.
   - `inventory.below_reorder`: alerts purchasing team of depleted stock.
4. **Scheduled Checks Engine (`ScheduledChecksEngine`)**:
   - 5 daily cron checks executing atomically:
     - Invoices past due (`balance_due > 0` and `due_date < today`).
     - Expired quotes (`status = 'sent'` and `valid_until < today`).
     - Opportunities closing soon (`stage NOT IN ('closed_won', 'closed_lost')` and within 7 days).
     - Delayed Purchase Orders (`status IN ('sent', 'partially_received')` and `expected_date < today`).
     - Low stock below reorder point (`Product.product_type = 'stock'` and stock $\le$ `reorder_point`).
5. **In-App Notifications (`notifications`)**:
   - Table `notifications`: `user_id`, `title`, `message`, `link`, `category`, `is_read`, `read_at`, `dedup_key`.
   - Deduplication via `dedup_key` prevents spamming users if jobs run multiple times.
   - API endpoints mounted at `/api/v1/notifications`:
     - `GET /`: list paginated notifications with `unread_only` filter.
     - `GET /unread-count`: lightweight polling endpoint for top navigation badges.
     - `PATCH /{id}/read`: mark single notification read with timestamp.
     - `POST /read-all`: mark all notifications read in one click.
6. **Dead-Letter Management Endpoints (`/api/v1/events/dead-letters`)**:
   - Superuser endpoints for querying quarantined events and triggering immediate replays (`POST /dead-letters/{id}/retry`).
7. **Frontend Notification Center & Top Bar Bell**:
   - Modern glassmorphic bell button in `AppLayout` with unread count badge.
   - Interactive dropdown with recent unread notifications and quick read toggles.
   - Dedicated `NotificationsPage` with category filters, full history, and an administrative "Dead-Letter Observability" dashboard.
