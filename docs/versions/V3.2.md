## 1. Executive Summary

Milestone V3.2 expands the automated inventory replenishment engine by connecting physical warehouse safety stock deficits directly to the procurement subledger. While Milestone V3.1 established localized warehouse reorder policies and inter-warehouse transfers (`sourcing_type = 'transfer'`), V3.2 automates the upstream procurement pipeline by translating stock shortages into batched draft **Supplier Purchase Orders** (`sourcing_type = 'purchase'`).

Key capabilities delivered in Milestone V3.2:
1. **Preferred Supplier Associations on Reorder Policies**: Added `preferred_supplier_id` directly to `WarehouseReorderPolicy` to support fine-grained supplier assignments per (warehouse, product).
2. **Three-Tier Sourcing Resolution Hierarchy**: Sourcing evaluation resolves suppliers hierarchically:
   - Level 1: Explicit policy `preferred_supplier_id`
   - Level 2: Catalog preferred vendor (`SupplierProduct.is_preferred == True`)
   - Level 3: Active vendor with the lowest unit cost (`SupplierProduct.last_unit_cost.asc()`)
   - Unfulfillable detection: If no active vendor is found, suggestions flag `NO_SUPPLIER_FOR_PRODUCT`.
3. **Automated Purchase Order Drafting (`auto_generate_replenishment_pos`)**:
   - Groups suggestions by `(preferred_supplier_id, warehouse_id)` into reviewable draft `PurchaseOrder` documents.
   - Computes gapless sequential numbering (`PO-YYYY-XXXXXX`).
   - Populates lines with VAT calculations (`subtotal`, `tax_total`, `grand_total`) adhering to the standard 12% Philippine VAT rate.
   - Computes expected delivery dates using policy and supplier lead times (`lead_time_days`).
   - Appends status history audit records without triggering managerial spend threshold locks prematurely.
4. **REST API Endpoint**: `POST /api/v1/inventory/replenishment/auto-generate-pos`.

## 2. Architecture & Sourcing Lifecycle

```
[ Warehouse Stock Deficit ]
           │
           ▼
[ Evaluate Sourcing Type ]
      │             │
 (transfer)     (purchase)
      │             │
      │             ▼
      │    [ Resolve Supplier Hierarchy ]
      │    1. Policy preferred_supplier_id
      │    2. Catalog SupplierProduct.is_preferred
      │    3. Cheapest active SupplierProduct
      │             │
      │             ▼
      │    [ Group by (Supplier, Warehouse) ]
      │             │
      ▼             ▼
[ Draft Stock ] [ Draft Purchase Order (PO-YYYY-XXXXXX) ]
[  Transfer   ] ├── Supplier & Warehouse address snapshots
                ├── Payment terms snapshot
                ├── VAT & Line totals (centavo-exact)
                └── Expected delivery date from lead_time_days
```

## 4. API Endpoints Delivered

| Method | Endpoint | Description | Scope / Permissions |
|---|---|---|---|
| `POST` | `/api/v1/inventory/replenishment/auto-generate-pos` | Automatically draft supplier purchase orders from purchase replenishment suggestions | `inventory:replenish:write` |
| `POST` | `/api/v1/inventory/reorder-policies` | Upgraded to accept `preferred_supplier_id` | `inventory:policy:write` |
| `PUT` | `/api/v1/inventory/reorder-policies/{id}` | Upgraded to update or unset `preferred_supplier_id` | `inventory:policy:write` |
| `GET` | `/api/v1/inventory/reorder-policies` | Upgraded to return `preferred_supplier_id`, `preferred_supplier_code`, `preferred_supplier_name` | `inventory:policy:read` |
| `GET` | `/api/v1/inventory/replenishment/suggestions` | Upgraded to evaluate supplier, estimated unit cost, and unfulfillable reason | `inventory:replenish:read` |
